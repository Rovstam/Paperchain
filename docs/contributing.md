# Contributing

## Set up

```bash
git clone <this-repo>
cd paperchain
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install -e ".[dev]"
python -m pytest -q
```

Pandoc is optional for development. The build test skips itself when pandoc is not on PATH; install it to exercise the whole pipeline.

## Layout

```
src/paperchain/
├── cli.py          argument parsing, JSON envelope, exit codes
├── manifest.py     paper.toml read/write
├── project.py      path resolution and upward search
├── extract.py      PDF/DOCX/TXT extraction and page maps
├── citations.py    syntax parsing and rendering
├── check.py        the verifier
├── convert.py      writes References/_text
├── import_cmd.py   original manuscript -> Paper/paper.md
├── library.py      CSL JSON bibliography loading
├── locking.py      hashes and read-only bits
├── build.py        pandoc, optional citeproc
├── init_cmd.py     template and adapter copying
├── doctor.py       environment checks
├── templates/      copied by `paperchain init`
└── adapters/       per-tool permissions
tests/              pytest, generated fixtures only
docs/               setup per OS, how it works, troubleshooting
```

Templates and adapters ship **inside** the package. An installed wheel cannot read a sibling `template/` directory, and keeping two copies would drift. If you add a template file:

- `foo/bar.md` is copied as `foo/bar.md`;
- `foo.md.tmpl` is copied as `foo.md`;
- `gitignore` and `gitattributes` become `.gitignore` and `.gitattributes`.

Text files get `{{program}}`, `{{title}}`, `{{slug}}` and `{{date}}` substituted.

## Rules of the code

- Python 3.10+. No runtime dependency except `pypdf` and `tomli` on 3.10.
- `pathlib`, `encoding="utf-8"` and `newline="\n"` for every text read and write.
- No shell-specific behaviour. One `os.chmod` path covers Windows and Unix.
- Failures are `PaperchainError` with a stable `code`. A new code must be added to [troubleshooting](troubleshooting.md).
- Every command returns the same JSON envelope and a meaningful exit code.
- Never make `check` depend on the network.

## Tests

Fixtures are generated by `tests/helpers.py`: a minimal valid PDF with real text, and a minimal DOCX zip. Do not commit real papers; they are copyrighted and make the suite slow.

Add a test when you change:

- citation syntax (valid and invalid forms);
- normalisation (ligatures, hyphenation, quotes);
- extraction (a new format, or a bug in the DOCX reader);
- hashing or lock behaviour;
- the JSON envelope or exit codes.

Windows and macOS are first-class. CI runs all three; run the tests locally on the OS you use before opening a pull request.

## Adding an adapter

See [adapters](adapters.md). Ship it only after running the checklist against the tool version you tested, and set `tested = true` only then.

## Releasing

1. Bump `version` in `pyproject.toml` and `__version__` in `src/paperchain/__init__.py`.
2. Run the tests on Windows, macOS and Linux (CI does this).
3. Build and inspect the wheel:

   ```bash
   python -m build
   python -m zipfile -l dist/paperchain-*.whl | grep -E "templates|adapters"
   ```

   The template and adapter files must be present, or `paperchain init` breaks for users.
4. Tag `v<version>` and publish to PyPI.
5. Tell users how to upgrade: `pipx upgrade paperchain`.

## Reporting a bug

Include `paperchain doctor --json` and `paperchain check --json`. Both avoid printing document contents. If the bug needs a reference file, reduce it to a synthetic fixture in `tests/` rather than attaching a copyrighted paper.
